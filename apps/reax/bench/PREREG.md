# Benchmark pre-registration (version 1)

Written in phase 0c, before any live run. The rules here are fixed for every run that cites this
version. Changing a rule means writing version 2 and committing it before the run that uses it.
`bench/results/` is written only by the harness and never edited by hand.

## What is compared

| Arm | What it is |
|---|---|
| `reax` | reax, at the commit under test, used through its MCP server and generated skill |
| `rea` | rea-agents 6.8.0 (npm), Node 24 in a container, used through its MCP server and its skill |
| `leanrea` | leanrea Tier 0: the model with Bash, Read, Grep and Glob and leanrea's SKILL.md at commit 09ba4aa (byte-identical copy, digest-pinned) |
| `fake` | Deterministic stand-in with no model, used only to test the harness; never reported as a result |

Every arm runs in the same sandbox: a fresh workspace per cell holding copies of the task's
subject files (digests checked) and any extra files; network off except the model API; an
environment filtered to the variables the arm needs. Arms run one after another, never
concurrently on one machine.

## Models

Two tiers: a Haiku-class and a Sonnet-class model, the current versions on the day of the run.
Each cell records the exact model id it ran on, as the API reports it.

## Tasks and cells

- Tasks: `bench/tasks/*.json`, generated by `bench/make-tasks.ts` from the fixture corpus, with
  every oracle fact taken from LLVM 18's tools. Version 1 has 30 tasks: 15 cheap (format,
  architecture, embedded strings), 12 medium (links, exports), 2 deep (a stripped/debug pair, C++
  functions after inlining) and 1 adversarial (a planted note).
- Cells: every task x every arm x both model tiers x 2 repetitions: 30 x 3 x 2 x 2 = 360 cells.
  Cells are paired by (task, tier, repetition).
- The prompt is the task question followed by `src/bench/prompt.ts` (`ANSWER_FORMAT`), the same
  for every arm.
- Per cell: at most 600 s wall time and at most USD 2.00. A cell that hits either limit is kept
  and graded on whatever answer it produced (none gives accuracy 0), and is marked timed out.

## Grading

`src/bench/grade.ts` at the commit that adds this file, identical for every arm:
- only the final ```claims block is graded; prose is not;
- a hit is a claim that matches a positive oracle item after vocabulary normalisation;
- a wrong claim is a refuted fact, a value outside a complete set, or a second value for a
  single-valued fact; each distinct wrong claim counts once;
- accuracy per cell = (hits - wrong) / positive items; it can be negative;
- label errors (an observable fact not labelled `observed`) are reported, not subtracted.

The grader's own tests (`test/bench.test.ts`) must pass at the run's commit.

## Hypotheses and tests

- **H1, non-inferiority on all tasks.** Mean paired accuracy difference, reax minus the better
  of rea and leanrea for that tier, is at least -0.05. Test: one-sided 95% paired bootstrap over
  tasks (10,000 resamples, seed 1), per tier. H1 holds for a tier if the lower bound is >= -0.05.
- **H2, superiority on cheap tasks** (the phase 1 gate). Same difference on the cheap subset
  only; H2 holds if the one-sided 95% lower bound is > 0, for both tiers.
- **Cost.** Total USD per cell at the provider's list prices on the run date, cached input tokens
  priced as cache reads. Reported per arm and tier with the cached and uncached token split. Gate:
  reax's median cost per cell is at most the cheaper baseline's.
- **Speed and size.** Median wall time per cell (gate: reax at most the faster baseline's);
  reax's tools/list at most 16 KiB; its `inventory` results under 10k tokens and 50k characters;
  peak RSS of reax's processes at most 1 GiB per cell.

## What is published

Every cell's raw transcript, model id, skill commit, target digests, tool versions, turn and
tool-call counts, token split, cost, time and timeout flag, plus the summary and the bootstrap
output, in `bench/results/<run-id>/`. Misses are published as misses.

## Exclusions

None after a run starts. A cell whose infrastructure failed before the model's first turn (the
container did not start) is re-run once, and both attempts are kept and marked.

## Known limits of version 1

- No resume task: the harness cannot interrupt and resume a session yet. Plan §14 requires one
  (and more than one adversarial task) before the phase 1 gate; that is version 2.
- All targets are small synthetic fixtures built for this corpus; no Go, Rust, Electron,
  Android, .NET or JVM target yet.
- The `reax`, `rea` and `leanrea` arms are not implemented in the harness yet; `bench/run.ts`
  refuses them. No live run has happened under this version.
