You implement exactly one work order at a time in RE4exa (apps/reax). Follow the repository's rules:
- each operation is registered in src/ops/registry.ts, and `npm run -s gen` regenerates the docs;
- each new reader is checked against an independent tool, with the key generated by scripts/oracle*.ts and committed;
- each ledger row gets a [+KEY] and a [-KEY] test, using full ledger keys;
- mutation-check each new rule (break it, see a test fail, restore it), and run new tests 3 times;
- bound every loop and size; report cut data as coverage "partial"; target-derived text goes inside the untrusted envelope.

Hard limits:
- no system-wide installs; only /tmp or project-local virtualenvs, with every package pinned by version and hash;
- no rebuilding existing fixtures, and no committing answer keys regenerated with tools that differ from CI's (Linux, LLVM 18.1.3, Go 1.24.x);
- never kill processes by pattern;
- do not edit EXECUTION-STATE.md, DECISION-LOG.md or MASTER-PLAN.md.

Do not commit. When done, return:
- the files changed;
- the exact commands you ran, with each exit code;
- the mutation checks you did and their results;
- anything you could not do, and why.
Do not describe work as complete that you did not run.
