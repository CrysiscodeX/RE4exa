## Scope

Flags: `parses_untrusted`, `uses_llm`. Not set: `distributed`, `executes_code`, `has_ui`, `heavy_compute`, `network_service`, `uses_crypto`.

security-tool: a defensive containment reference (internal Docker network, allowlisting DNS and proxy, hardened agent container, write approval, tool-call log, step cap, kill switch) demonstrated on a 153-line tool-using agent, which is the test subject rather than the product. Flags set from the code: uses_llm on, which the automatic flags missed (agent/agent.py:108-114 calls Ollama's /api/chat with tool schemas for qwen3:4b); parses_untrusted on (the agent ingests web pages and workspace files, including a prompt-injection fixture); executes_code off (tools are fixed Python functions for file I/O, HTTP GET and DNS lookup, with no shell or code tool); network_service off (DNS, proxy and Ollama listen only on the internal compose network, and no ports are published to the host); heavy_compute off (single demo tasks on a 4B local model, not material energy use); has_ui off (a CLI with a y/N prompt); uses_crypto and distributed off. Red-line decisions: PRV-3 is 1, not 0, because README.md:61 declares MIT although there is no LICENSE file; SEC-7 is 1, not 0, because the URL tool's missing scheme and host allowlist is reachable from untrusted content but the tool only reads and runs as a non-root user on a read-only root filesystem with no secrets in the shipped configuration (recorded as a high gap); EPI-5 is 1, not 0, because the demonstrated controls are backed by recorded runs and the overstatements are location and scope errors rather than claims contradicted by measurement; SEC-6 and PRV-1 pass. Static review of commit 5aba6b8 (shallow clone, one commit); nothing was run.

- Question: Does the containment stop a prompt-injected agent from sending data out? In the recorded run, the DNS lookup was refused and logged (run_injection_1.txt:8-11, coredns_log.txt:10). No recorded run exercises the proxy's refusal path, nothing is tested automatically, and the boundary images are unpinned.
- Question: Does containment protect what the user sees? No. The same run returned a wrong company and deal size, and an unrelated task disclosed customer deal sizes (run_injection_1.txt:31-33, run_approval_allow.txt:19).
- Question: Is the repository reusable as a reference? Partly. The network layout and container hardening are sound patterns worth extracting, but there is no license file and no tests, the URL tool sits outside the file confinement, and the checklist's claims do not match the tree.
- Not examined: Runtime behaviour: nothing was built or run; containment was judged from configuration and the recorded transcripts; Contents and default configuration of the pulled images (ollama/ollama, vimagick/tinyproxy, coredns, python:3.12-slim); Docker daemon, kernel, seccomp and AppArmor defaults and host networking, none of which the compose file sets; The external incident report cited at README.md:5 and AGENT_SAFETY_CHECKLIST.md:8 (no web access); Git history beyond the single commit
