## Scope

Flags: `distributed`, `executes_code`, `has_ui`, `network_service`, `parses_untrusted`, `uses_crypto`, `uses_llm`. Not set: `heavy_compute`.

agent-harness: T3 Code runs provider coding agents (Codex, Claude, Cursor, Grok, OpenCode, Pi, ACP) that execute commands on the user's machine and serves them to web, desktop and mobile clients over a local server (127.0.0.1:3773), MCP and a cloud relay. All flags are set except heavy_compute, because model inference happens at the providers. This is a static review of commit 7e289ae1 (shallow clone), excluding the vendored .repos/ trees.

- Question: Does the durable orchestration kernel avoid repeating side effects after a crash? Mostly yes. Commits happen in one transaction, receipts deduplicate commands, replay-safe effects are requeued and process-bound ones cancelled, and auto-resume is capped at 3 (EffectOutbox.ts:123-142,496-530; RestartContinuation.ts:33). Remaining risks: a documented power-loss window (synchronous=NORMAL) and no abrupt-kill fault injection.
- Question: Is telemetry consent a red line (PRV-1 at 1 or below)? No. Use is disclosed in a docs page, a first-run notice and the privacy policy, and no prompts or content are sent. It scores 2: on by default, opt-out only by environment variable, no DO_NOT_TRACK, and an 'anonymous' label despite linkable hashed provider-account ids.
- Question: Are agents run with least agency by default? No for threads: the default is Full access, which maps to Codex dangerFullAccess with approvals off and to Claude bypassPermissions, with no T3 sandbox. Yes for outside MCP agents, which default to read-only with mode ceilings and per-tool access classes.
- Not examined: Runtime behaviour: nothing was built or run (static review), so there was no oracle run, quickstart run or latency measurement.; Git history: the shallow clone has 1 commit, so contributor concentration, release cadence and breaking-change rate were not measured.; Branch-protection and required-review settings, GitHub secret scanning and published advisories, all configured outside the repo.; infra/relay (Cloudflare Worker, Postgres, Clerk) beyond notification payloads and monitoring queries.; apps/mobile native modules (Swift/Kotlin), native/* Rust and C helpers, and the vendored libghostty binaries.; Whether tsc-rs enforces the Effect language-service diagnostics during CI typecheck.; Whether the background-service log file captures the one-time startup pairing URL printed to stdout.; CSRF and WebSocket-origin posture of cookie-authenticated endpoints under the production wildcard CORS policy (apps/server/src/http.ts:258-275).; Main-process validation of IPC messages from preview webview guests that run without context isolation (apps/desktop/src/preview/PickPreload.ts).; .repos/ vendored reference subtrees (skipped by the probes and by this review).
