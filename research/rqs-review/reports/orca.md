## Scope

Flags: `distributed`, `executes_code`, `has_ui`, `network_service`, `parses_untrusted`, `uses_crypto`, `uses_llm`. Not set: `heavy_compute`.

Profile agent-harness: an Electron desktop IDE plus CLI, headless orcad server, mobile companion and cloud relay that launches and orchestrates third-party coding-agent CLIs on the user's machine; flags all set except heavy_compute, because it runs agents, executes commands, listens on loopback/LAN sockets, parses agent terminal output, repo files and web pages, uses NaCl/Ed25519/AES-GCM, and ships signed installers, while model inference runs in the user's own agents and providers. Static review of commit 997d34b0 (shallow clone); nothing was built or run.

- Question: Is Orca safe by default for running agents on untrusted repositories? No: agents launch with permission-bypass flags, third-party folder trust is pre-written and committed setup scripts run by default; isolation is opt-in through per-workspace recipes, and one docs page wrongly calls the worktree a sandbox (AGT-2, OPS-3, EPI-5).
- Question: Can an agent drive Orca without reading prose, and are retries safe? Mostly: a versioned JSON envelope, a generated command catalog, typed error codes with next steps and idempotent retry keys exist; effect annotations, argument schemas, distinct exit codes and an MCP endpoint are missing (INT-1, INT-2, INT-4, INT-5).
- Question: Are the security process, release and supply chain ready for the EU CRA dates (reporting from 2026-09-11, main obligations from 2027-12-11)? No: signed CI-built releases exist, but there is no SECURITY.md, SBOM, provenance, dependency scanning, support period or regulatory position, and 555 of 570 action references use mutable tags (SEC-1 to SEC-5, EVO-4, PRV-4).
- Not examined: Runtime behaviour: nothing was built, installed or run, so oracle step 4 (independent answer key run against the product) was not performed and the actual agent-context --json size is an estimate; Git history and contributor concentration (shallow clone, one commit); GitHub repository settings: branch protection, required reviewers, Actions default token permissions, release notes on GitHub Releases; mobile/ (Expo app) and cloud/ (relay, Terraform, 40+ cloud workflows) beyond the CI files cited; Native code: native/computer-use-macos (Swift), Rust Windows launcher and hook, C/C++ addons, Python and PowerShell computer-use runtimes; Packaged artifact contents (asar license files, Electron fuse state) and electron-updater signature checks at runtime; WCAG conformance of the UI and keyboard and screen-reader behaviour; Full call graph of every worktree-create entry point for the setup-script trust gap (the finding rests on the main-process gate and the CLI default); PostHog project configuration and server-side redaction at ingest
